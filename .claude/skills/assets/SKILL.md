# Managing Static Assets

## Large assets (models, textures, audio, video) — `static/`

Files in the project-root `static/` folder are **content-addressed**: the R2 key
carries an md5 fragment, so they upload once, cache forever, and only re-upload
when their bytes change. Publish serves them from the bucket's own custom
domain (`static.<yourdomain>`), so Cloudflare's CDN answers the request —
no Worker invocation, and `Range` requests work for progressive loaders.

```
static/
  models/char2.ugm
  tex/stone.ktx2
```

Reference them through the generated module — never hand-write the URL, since
the hash changes with the content:

```tsx
import { staticUrl, resolveStaticUrl } from '../../shared/StaticAssets'

const res = await fetch(staticUrl('models/char2.ugm'))  // tsc-checked
const maybe = resolveStaticUrl(`models/${name}.ugm`)     // runtime, may be null
```

`shared/StaticAssets.ts` is generated by `ugly-app build:static` (which
`ugly-app build` runs for you) and is **committed**. A typo or a deleted asset
is a tsc error, not a production 404. Dev serves the files off disk at
same-origin, so a newly added asset works before it has ever been published.

Publish uploads only what changed and deletes any asset that no build from the
last 7 days references. Tune in `.uglyapp`:

```json
"staticAssets": { "dir": "static", "retentionDays": 7 }
```

**Requires a provisioned app domain.** Publish fails rather than shipping URLs
nothing serves.

## Small assets (icons, favicon) — `client/assets/`

Place in `client/assets/` — Vite serves them at `/assets/filename.ext` and they
ship under `builds/{buildId}/`. These get a **new URL on every deploy**, so
every user re-downloads them each release — keep this folder for small files.
`favicon.ico`, `icon.png` and the OG image must stay here: the PWA manifest,
social scrapers and the app-store card address them at fixed URLs.

```tsx
// Reference in React
<img src="/assets/logo.png" alt="Logo" />
```

## `hostBundle` — put the vite bundle on the CDN too

```json
"staticAssets": { "hostBundle": true }
```

Opt-in, in `.uglyapp`. Publish provisions the static host, then vite emits every
bundle URL against it. Content-addressed URLs mean an unchanged chunk keeps its
URL across deploys, so each deploy uploads a few KB instead of the whole bundle.

The first deploy only provisions — the bundle moves on the next one. Don't try
to short-circuit that: a single pass would point the bundle at a hostname whose
TLS certificate may not have issued yet.

**What this changes for you: the bundle is now cross-origin.** Two consequences
worth knowing before you debug them:

- `new Worker(new URL('./x.worker.ts', import.meta.url))` still works —
  `bootstrapApp` shims it. The constructor *rejects a cross-origin script URL
  outright* and no CORS/CORP header lifts it, so the shim routes it through a
  same-origin `blob:`. **`SharedWorker` is not shimmed** (unique blob URLs would
  break sharing); don't reach for it.
- Register service workers by root-absolute path (`/sw.js`). `register()`
  resolves against the document, so root paths stay same-origin.
- A bare `<img src>`/`<audio src>` pointed at the static host is a no-CORS
  request. It's covered by a zone CORP rule, but if that rule is ever missing
  the asset is blocked by COEP as a healthy 200 that never renders — use
  `crossOriginProps()` when in doubt.

## Generating assets with imageGen
```ts
app.registerFunction('createAsset', async (ctx, input: { prompt: string; name: string }) => {
  // Generate image
  const tempUrl = await ctx.imageGen.generate(input.prompt)
  // Extract temp key from URL
  const tempKey = tempUrl.split('/temp/')[1]
  // Promote to public assets
  const publicUrl = await ctx.storage.moveToPublic(tempKey, `assets/${input.name}.png`)
  return { publicUrl }
})
```

## Recommended asset organization
```
static/         — LARGE, rarely-changing: models, textures, audio, video
  models/       (content-addressed, CDN-served, uploaded once)
  tex/
client/assets/
  icons/        — UI icons
  backgrounds/  — Background images
  generated/    — imageGen output (promoted to public bucket)
public/         — Static files served at root (favicon.ico, robots.txt)
```

## Image sizes for flux schnell
- Default: 1024×1024
- Banners: use prompt guidance ("wide landscape format", "16:9 ratio")
- Icons: generate at 1024×1024, scale down in CSS
